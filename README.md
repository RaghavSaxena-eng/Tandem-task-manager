# Tandem: Collaborative Task Manager

A real-time task manager for small teams. People sign up, create **workspaces**, add teammates, and plan work on **boards** of **tasks**. What each person can do depends on their role, and every change shows up instantly for everyone else viewing the board.

**Live demo:** _add your deployed URL here_ (sign in with the demo account: `demo@tandem.dev` / `demo1234`)

**Stack:** React (Vite) · Node.js · Express · MongoDB (Mongoose) · Socket.io · JWT

## What it demonstrates

- **Authentication:** register / login with bcrypt-hashed passwords and signed JWTs; protected routes on the client and API.
- **Role-based access control (owner / member)** applied at three levels: workspaces, boards and tasks. Permissions are enforced on the server by one middleware (`server/src/middleware/workspaceAccess.js`), never only in the UI.
- **Relational data in MongoDB:** users, workspaces (with embedded membership and role), boards and tasks, linked by references and populated on read.
- **Real-time updates:** Socket.io rooms per workspace. Sockets authenticate with the JWT, membership is re-checked before joining a room, and removed members are evicted immediately.
- **Product details:** optimistic drag-and-drop between columns with rollback on failure, reconnect catch-up, accessible dialogs, responsive layout.

## Permission matrix

| Action | Owner | Member | Not in workspace |
| --- | :---: | :---: | :---: |
| View workspace, boards, tasks | yes | yes | no (404) |
| Create tasks | yes | yes | no |
| Edit / move a task | any task | only tasks they created or are assigned to | no |
| Reassign a task | any task | only tasks they created | no |
| Delete a task | any task | only tasks they created | no |
| Create / rename / delete boards | yes | no | no |
| Add, remove, promote members | yes | no (can leave) | no |
| Rename / delete workspace | yes | no | no |

A workspace must always keep at least one owner. Assignees must belong to the workspace, and removing a member unassigns their tasks.

## Run it locally

Requirements: Node.js 18+ and a MongoDB instance (local, or a free MongoDB Atlas cluster).

```bash
# 1. install both apps
npm run install:all

# 2. configure the API
cp server/.env.example server/.env      # then edit MONGODB_URI and JWT_SECRET

# 3. (optional) load demo data: demo@tandem.dev / demo1234
npm run seed

# 4. start both servers in two terminals
npm run dev:server     # http://localhost:5000
npm run dev:client     # http://localhost:5173
```

The Vite dev server proxies `/api` and `/socket.io` to the API, so no extra frontend configuration is needed locally.

### Tests

```bash
npm test
```

The API tests (`server/tests/api.test.js`) run against an in-memory MongoDB and cover auth, the owner/member/outsider permission rules, the last-owner guard, and real-time delivery over Socket.io. The first run downloads a MongoDB binary, so it needs internet access.

## Deploy it (free tiers)

You need three things: a database, the API, and the frontend.

### 1. Database: MongoDB Atlas
1. Create a free M0 cluster at <https://www.mongodb.com/atlas>.
2. Create a database user, and under **Network Access** allow `0.0.0.0/0` (Render's IPs change).
3. Copy the connection string (`mongodb+srv://...`) and add a database name, e.g. `.../tandem`.

### 2. API: Render
1. Push this repo to GitHub, then in Render choose **New > Blueprint** and select the repo (it reads `render.yaml`). Or create a **Web Service** manually with root directory `server`, build command `npm ci --omit=dev`, start command `npm start`.
2. Set environment variables: `MONGODB_URI` (from Atlas), `JWT_SECRET` (auto-generated by the blueprint), `NODE_ENV=production`, and `CLIENT_URL` (the frontend URL from step 3; you can set it after deploying the frontend, then redeploy).
3. After the first deploy, open `https://<your-api>.onrender.com/api/health`. It should return `{"status":"ok"}`.
4. Load the demo data once against Atlas: `MONGODB_URI="<atlas uri>" npm --prefix server run seed` (run on your machine).

Free Render services sleep after inactivity, so the first request can take about 30 seconds. Open the site once before showing it to someone.

### 3. Frontend: Vercel (or Netlify)
1. Import the repo, set the **root directory** to `client`.
2. Add the environment variable `VITE_API_URL` = your API URL (no trailing slash), e.g. `https://tandem-api.onrender.com`.
3. Deploy. `client/vercel.json` already rewrites all routes to `index.html` for client-side routing. (On Netlify, add a `_redirects` file with `/* /index.html 200`.)
4. Copy the frontend URL into the API's `CLIENT_URL` setting on Render and redeploy the API so CORS and Socket.io accept it.

## API overview

All routes except `/api/auth/register` and `/api/auth/login` need `Authorization: Bearer <token>`.

| Method | Route | Role |
| --- | --- | --- |
| POST | `/api/auth/register`, `/api/auth/login` | public |
| GET | `/api/auth/me` | any user |
| GET / POST | `/api/workspaces` | any user |
| GET | `/api/workspaces/:id` | member |
| PATCH / DELETE | `/api/workspaces/:id` | owner |
| POST | `/api/workspaces/:id/members` | owner |
| PATCH | `/api/workspaces/:id/members/:userId` | owner |
| DELETE | `/api/workspaces/:id/members/:userId` | owner, or the member themself |
| GET | `/api/workspaces/:id/boards` | member |
| POST | `/api/workspaces/:id/boards` | owner |
| GET | `/api/boards/:id` | member |
| PATCH / DELETE | `/api/boards/:id` | owner |
| GET / POST | `/api/boards/:id/tasks` | member |
| PATCH / DELETE | `/api/tasks/:id` | see permission matrix |

Socket.io events broadcast to a workspace room: `task:created`, `task:updated`, `task:deleted`, `board:created`, `board:updated`, `board:deleted`, `member:changed`, `workspace:updated`, `workspace:deleted`.
